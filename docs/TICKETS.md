# TICKETS — tracer bullets بالتبعيات

كل تيكت = شريحة عمودية تشتغل لوحدها وتخضع للاختبار قبل اللي بعدها. الترتيب بالتبعيات.

## T1 — Server: خط أنابيب الجمع (tracer bullet)
**يعتمد على:** لا شيء.
**الشغل:** باك إند Node+TS يجيب RSS من 8 مصادر مصرية (خليط: RSS مباشر + Google News RSS)، يحوّل لمخطط `Article` موحّد، يزيل التكرار، يخزّن في SQLite، ويعرض:
- `GET /api/feed` (أحدث الأخبار)
- `GET /api/sources`
- `GET /api/articles/:id`
**مصادر البداية:** اليوم السابع (RSS مباشر) + الجزيرة، BBC عربي، CNN عربي، سكاي نيوز، RT عربي (RSS مباشر) + العربية، الأهرام، المصري اليوم، مصراوي (Google News RSS `site:`).
**الخروج:** `curl /api/feed` يرجع JSON فيه ≥10 أخبار من ≥5 مصادر.

## T2 — Mobile: هيكل التطبيق + الفييد
**يعتمد على:** T1.
**الشغل:** Expo + expo-router + TypeScript، اتجاه RTL عربي. شاشة فييد رئيسي (قائمة أخبار: صورة + عنوان + مصدر + وقت)، pull-to-refresh، فتح المقال (WebView أو Linking للمصدر الأصلي).
**الخروج:** التطبيق يفتح على موبايل ويعرض فييد T1.

## T3 — التصنيفات + الترند + صفحة مصدر
**يعتمد على:** T1, T2.
**الشغل:** Server: `GET /api/categories`, `GET /api/trending`, `GET /api/sources/:id/articles`. Mobile: تبويب/شاشة تصنيفات، شاشة ترند، صفحة مصدر (أخباره + معلوماته).
**الخروج:** فلترة التصنيفات صح، الترند مرتب، صفحة المصدر تعرض أخباره.

## T4 — حسابات + متابعة + فييد مخصص
**يعتمد على:** T1, T2.
**الشغل:** مصادقة (Supabase Auth أو بديل JWT — Bolt يحسم ويبرر)، جدول users + follows، `POST /api/me/follows` + `GET /api/me/feed` (مخصص حسب المتابَع). Mobile: تسجيل دخول/إنشاء حساب، زر متابعة، شاشة "متابَعتي".
**الخروج:** مستخدم يعمل sign up/in، يتابع مصادر، ويشوف فييد مخصص.

## ملاحظات تنفيذ
- ابدأ T1 (tracer bullet) وخلّصه قبل T2.
- T3 وT4 ممكن يتوازوا بعد T2.
- كل تيكت ينتهي باختبار/فحص قبول مكتوب في التيكت نفسه.
- اكتب كود بالإنجليزية، الواجهة عربي RTL.
